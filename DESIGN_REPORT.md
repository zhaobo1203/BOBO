# 微信群消息监听系统 - 设计方案报告

---

## 一、项目概述

### 1.1 项目目标
开发一个微信群消息监听系统，用于实时获取并存储微信群的文字消息。

### 1.2 核心功能
- 自动识别登录的微信账号
- 实时监听指定微信群的新消息
- 提取并存储纯文字消息内容
- 支持多电脑、多微信账号运行

### 1.3 技术约束
- 仅支持 Windows 操作系统
- 仅处理文字消息，不处理图片、视频、表情包、链接等
- 需要微信客户端运行配合

## 五、消息监听方案

### 5.1 主方案：实时监听

**原理：** 通过 WCDB DLL 直接连接微信的数据库，监听数据库变更事件。

**特点：**
- 秒级实时性
- 资源占用低
- 需要有效的数据库密钥

**技术实现：**
```
微信进程 ←──WCDB DLL──→ 微信数据库
     │                      │
     └──────变更事件─────────┘
              │
              ▼
        消息监听回调
```

### 5.2 退避方案：准实时轮询

**触发条件：**
- 实时监听连续失败 **3 次**
- 实时监听服务不可用超过 **1 分钟**

**轮询策略：**
- 轮询间隔：**10-20 秒**（可配置）
- 增量拉取：基于 `create_time` 或 `local_id` 只获取新消息

**自动恢复：**
- 检测到实时监听可用后，自动切回主方案

## 七、账号识别方案

### 7.1 账户ID格式支持

微信支持多种账户ID格式：

| 格式 | 示例 | 说明 |
|------|------|------|
| wxid格式 | wxid_abc123 | 微信默认分配的ID |
| 自定义ID | ToweR | 用户自定义的微信号 |
| 带后缀格式 | wxid_abc123_8d63 | 微信4.x数据目录中的格式 |

### 7.2 当前登录账号检测

```
┌─────────────────────────────────────────────────────┐
│            当前登录账号检测方法                       │
├─────────────────────────────────────────────────────┤
│                                                     │
│  方法A: 文件修改时间判断                             │
│  ├─ 检查各账号目录的 db_storage 修改时间             │
│  ├─ 最近修改的目录 = 当前/最近登录账号               │
│  └─ 精确度: 高（微信退出前会写入数据）               │
│                                                     │
│  方法B: 进程句柄关联                                 │
│  ├─ 获取微信进程句柄                                 │
│  ├─ 枚举进程打开的文件句柄                           │
│  └─ 匹配正在使用的数据库文件 → 确定账号              │
│                                                     │
│  方法C: 内存扫描时自动识别                           │
│  ├─ V4内存扫描时，内存中包含当前账号信息             │
│  └─ 密钥获取结果中包含账户ID                         │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**推荐方案：方法A + 方法C 组合**
- 文件修改时间快速定位（秒级判断）
- 内存扫描时二次确认

## 八、数据存储方案

### 8.1 存储技术
- **数据库类型**：SQLite
- **存储位置**：程序运行目录下 `data/messages.db`

### 8.2 数据表结构

```sql
CREATE TABLE IF NOT EXISTS group_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sender_nickname TEXT NOT NULL,
    message_content TEXT NOT NULL,
    send_time DATETIME NOT NULL,
    group_name TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 索引优化查询
CREATE INDEX IF NOT EXISTS idx_send_time ON group_messages(send_time);
CREATE INDEX IF NOT EXISTS idx_group_name ON group_messages(group_name);
```

### 8.3 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INTEGER | 是 | 自增主键 |
| sender_nickname | TEXT | 是 | 发送者昵称 |
| message_content | TEXT | 是 | 消息内容（纯文字） |
| send_time | DATETIME | 是 | 消息发送时间 |
| group_name | TEXT | 是 | 群名称 |
| created_at | DATETIME | 是 | 记录入库时间 |

### 8.4 数据示例


## 十、关键技术点

### 10.1 微信进程管理
- 检测微信进程是否运行
- 终止所有微信进程
- 自动启动微信客户端

### 10.2 数据库解密
- 微信使用 SQLCipher 加密数据库
- 密钥为 32 字节（64 位十六进制）
- 需要通过内存扫描或 Hook 获取密钥

### 10.3 群消息提取
- 群聊 ID 格式：`数字ID@chatroom`
- 从 `packed_info` (protobuf) 解析发送者信息
- 支持群名片显示

### 10.4 消息内容解码
- 部分消息使用 zstd 压缩
- 需要检测并解压缩
- 仅提取纯文字内容
